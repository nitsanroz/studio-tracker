# Studio&more Tracker

Custom task + time tracker for the **Studio&more** design studio (~8 active designers, Tel Aviv, Sun–Thu work week). Replaces Everhour + Asana + a Google Sheets weekly plan. This app is now the **single source of truth** for new work. Two standing exceptions to "don't re-pull": **Everhour is still live** (the team hasn't switched over for time logging — nightly cron + manual button, see v0.99.9), and **Asana is being re-pulled once, deliberately**, for the pre-Everhour comment history that was never imported (2026-07-28 entry). Neither is a reason to re-pull anything else — the deleted executive-team boards in particular stay deleted.

## Domain model
- Hierarchy: **Clients → Sections → Tasks** (the Projects layer was removed 2026-07-11 by migration 0007; `projects` table + `project_id` columns remain in DB for legacy import mapping only — the app never reads them).
- Every **time entry requires a description** (mandatory).
- Per-client non-billable **"«Client» keys"** task: admin moves hours into it before Sunday client reports.
- **Billable** is driven by `clients.billable` (migration 0009). Marking a client "Internal" (Settings→Clients) flips its existing tasks non-billable; new tasks inherit the client flag. Internal clients: **Studio, OFFF tlv, Imported / Unsorted**.
- **Client reports are published snapshots**: `report_links.snapshot` (jsonb) is frozen on Publish — permanent URL per client, clients never see live hours. Payment periods are fully custom per client (`client_billing_periods`: label/from/to/hour_cap/advance_hours/paid).
- Past employees (Liza, Sofia) stay in data as **deactivated**.

## Access control (intentional design)
- **Studio-wide READ visibility is intentional** (decided 2026-07-24): every signed-in member can read all tasks/time entries/clients/plan (RLS `read all`). Members seeing each other's hours is accepted for this 8-person studio — the `/reports` "member sees own hours" and admin-only nav are UX scoping, not security boundaries.
- **WRITES are enforced in the DB, not just the UI:** admins = full; members = own time entries (`own time *` policies) + only the collaborative task columns (migration 0011 trigger). Privileged task fields (billable/estimate/due/title/status/assignment) are admin-only server-side.
- **Genuinely sensitive tables stay admin-only** (no `read all`): `member_hr`, `member_notes`, `finance_*`, `client_billing_periods`.
- **Public routes** are token-gated + service-role only: `report/[token]` ships a snapshot that is **sanitized server-side** (hidden tasks/columns physically removed — never sent to the browser); `intake/[token]` uploads go through an extension allowlist (`src/lib/uploads.ts`, no HTML/SVG/JS) with a server-forced Content-Type + a DB-based rate limit.

## Session gotcha (PII)
Once sensitive PII from the HR sheet (national IDs, salaries, addresses) enters a session, the auto-mode safety classifier blocks all of Claude's Bash/preview tool calls for the rest of that session — not fixable via permissions. Fix: start a fresh session. In such a session the user must run build/deploy/git themselves.

- 2026-07-28 — data — **Three conventions Nitsan supplied after reviewing the CSV, all now encoded.** (1) **ROLL-UP PARENTS — the big one.** A parent task's title figure is the SUM of its subtasks: `"Q&A Movies - 128.25h"` has 7 children (`Storyboards - 34h`, `Design (70)- 50h`, `Animation - 18h`, …) that add up to the same 128.25h, and the import flattened parents and children into sibling tasks — so counting both **doubles every rolled-up figure**. Roughly two thirds of the unsorted set are subtasks. Decision: **children win, parent contributes 0**, with a guard — a parent is only zeroed when at least one of its children is present AND carries hours (`rollup-parent-kept-no-children` flags the rest, where the parent's figure is the only surviving record). Section names follow the same rule one level up: `Movies - 171.75h` ≈ the sum of its **top-level** tasks only, which is why `sections.legacy_hours` is display-only and never added to a client total. Parent shape comes from Asana (`parent.gid`, `num_subtasks`) and is cached to `data/asana/parents.json` by `fetch-asana-stories.mjs`; **without that file the reconciler warns loudly and does NOT zero anything** rather than silently double-count. (2) **`key` / `מפתח` rows are hours REDUCTIONS, not work** — `"מפתח שנעשה - 18.25h"` is a note recording how big a reduction was. Counted in **neither** direction per Nitsan: adding overstates delivery, negating would re-deduct something the studio's sheet had already netted off. Matched by `KEY_ROW` (guarded so "Keyboard" doesn't trip it) and flagged `key-reduction-not-counted`. (3) Budget **ranges** store the **high end** in `estimate_hours` (the ceiling quoted to the client); the low end rides along in the review CSV's `budget_low` and the full range survives in `legacy_title`. Note-like rows ("--- Keys ---", "Template Instructions", "Action Items") are **kept as tasks** — they carry no hours so they cannot distort a total. Client mapping confirmed by Nitsan against Asana: the `Website (232+61/134)…` and `Movies - 171.75h` sections and the `Storyboards - 34h` subtask are all Volta Solar; `Yoco new website - 67h` is Yoco.
